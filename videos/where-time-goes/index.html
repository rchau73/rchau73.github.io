Where a team of AI agents loses time

The agents write code in minutes. In October 2026 the time went elsewhere: conflicts on shared files, waiting for a person, and reviews of very large changes. Each problem, its number, and what fixed it.

About this page. It shows the agentic approach: how AI agents and people share the work. It is not a detailed account of the implementation. For the scripts, the agents' rules and the full workflow, see the repository on GitHub.

What the film shows

  1. 0:04
    1 · Merge conflicts. 29 of 171 merges on main had a conflict (14 to 28 October), and 26 PRs were sent back for a new Dev agent run. Every PR edited the same shared docs: CLAUDE.md was changed by 98 of 171 PRs, with whole sections on one line, and git merges line by line. Fix: one doc per folder, one sentence per line, sorted lists. Send-backs went from 23 in 92 PRs to 3 in 18.
  2. 0:15
    2 · Waiting on a person. The median agent PR is built in 17 minutes, reviewed by AI in 6, and live 4 minutes after the merge. 60 % of agent PRs change a policy (trading rules, risk, config, CI) and wait for me: since 30 October a median of 12 hours. Build, review and deploy take minutes; the wait for my approval takes hours.
  3. 0:26
    3 · Huge PRs, partial reviews. The median agent PR changes 608 lines, about half of them tests, and 43 of 182 changed over 1,000. One review read a 2,381-line diff to line 2,000 and marked it clean. Fix: the diff goes to the reviewer per file, and a partial read is "incomplete", never "clean".
  4. 0:36
    Agents write the code fast. My job: remove what slows them.
