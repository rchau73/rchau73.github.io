DevOps for a team of AI agents

Every 6 minutes a scheduler wakes the agents that work on optionsBot, a trading system I run on an exchange's test environment. CI, deploys and releases do the rest; the changes that carry risk wait for a person.

About this page. It shows the agentic approach: how AI agents and people share the work. It is not a detailed account of the implementation. For the scripts, the agents' rules and the full workflow, see the repository on GitHub.

What the film shows

  1. 0:04
    The scheduler. One macOS launchd job, every 360 seconds. Each tick runs, in order: deploy.sh (main to the mvp environment, health check, cards to Done), pr_gate.sh (CI green → ready; reviewed clean → merge), the Reviewer agent, the Dev agent (one Ready card → a pull request) and the PM agent (triage, epics, board ranking). Daily and weekly jobs add DORA metrics, flaky-test checks, backups and reports. The Dev and Reviewer agents each work in their own git worktree.
  2. 0:12
    One ticket in the logs. Ticket #553 on 30 October 2026, local time (UTC−3): tagged with its epic at 16:00, the Dev agent starts at 16:08, the pull request with tests opens at 16:31, CI is green at 16:36, I merge it at 16:40 (it changes a trading rule, so a person merges it), it is deployed and healthy at 16:45 and the card moves to Done. From epic to Done in 45 minutes.
  3. 0:22
    CI on GitHub Actions. Every push and pull request runs a secret scan, lint, tests under the race detector, a coverage floor, the frontend build, a vulnerability scan and a Docker build.
  4. 0:31
    Audited releases. Every deploy is recorded in deploys.tsv. Stable moves only by release: after 3 days on mvp, or by an escalation whose reason is kept on record.
  5. 0:38
    Engineering excellence, automated. Judgement, kept human.
